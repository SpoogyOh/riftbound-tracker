# Repository conventions

## Guiding principle

Keep It Simple, But Significant. Prefer a small number of components and incremental changes that deliver a clear user benefit.

## Language

- Use English for repository documentation, new or revised developer comments, identifiers, commit messages, pull request titles/descriptions, and issue text.
- Reply to the user in the language they use, unless they request another language.
- Treat the app's user-interface language as a separate product/localization decision. An English documentation change does not require translating existing UI strings.
- Preserve original language in quotations, upstream card data, and historical records such as `chat-verlauf.md`.

## Generated files

- `cloud.js` is generated from `src/` by `npm run build:browser`; do not edit the bundle directly.
- `cards.js` is generated by `scripts/import-openrift.mjs` (`npm run catalog:update`). Make catalog transformation changes in the importer.
- `riftbound_tracker.html` is generated by `scripts/build-standalone.mjs` (`npm run standalone:build`). Make interface and behavior changes in the shared source files first.
- Keep collection quantities separate from the generated card catalog, and preserve existing quantities when changing catalog IDs or backup formats.

## Database

- Use versioned migrations in `supabase/migrations/` for schema changes. Add a new migration after a migration has been deployed.
- Keep owner-scoped data private with explicit grants and Row Level Security; test both allowed and denied operations.
- Run `npm run test:database` after changing database behavior. PGlite tests do not replace hosted Auth/Data API integration checks.
